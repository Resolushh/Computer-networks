# Занятие 16 — TCP и UDP в Wireshark

## Задание

Сделать три скриншота в Wireshark: два TCP-пакета с разными флагами и один UDP-пакет.

## Разбор пакетов

Для работы использован захват с интерфейса Ethernet. TCP-пакеты найдены с помощью фильтра `tcp`, а UDP — с помощью `udp`. На каждом скриншоте раскрыты параметры выбранного пакета.

### 1. TCP с флагом ACK

У пакета № 11 установлен флаг **ACK** — это видно в строке `Flags: 0x010 (ACK)`. Он подтверждает получение данных и сам передаёт ещё 1400 байт. Флаги SYN и FIN в этом пакете не установлены.

Пакет отправлен с `192.168.3.6:60076` на `193.233.112.68:443`.

![TCP-пакет с флагом ACK](screenshots/01_tcp_ack.png)

### 2. TCP с флагами SYN и ACK

У пакета № 4396 установлены сразу два флага — **SYN и ACK**. В строке Flags указано `0x012 (SYN, ACK)`. Так сервер отвечает на запрос клиента при установлении TCP-соединения. Данных в этом пакете нет.

Ответ идёт с `4.176.49.0:443` на `192.168.3.6:61440`.

![TCP-пакет с флагами SYN и ACK](screenshots/02_tcp_syn_ack.png)

### 3. UDP

На третьем скриншоте выбран UDP-пакет № 4481. В раскрытом разделе **User Datagram Protocol** видны порт отправителя **19318** и порт получателя **57147**.

Пакет идёт с `104.29.156.0` на `192.168.3.6`. Длина UDP-датаграммы — **230 байт**: 8 байт заголовка и 222 байта данных. Флагов SYN и ACK у UDP нет.

![UDP-пакет с раскрытыми параметрами](screenshots/03_udp.png)

## Вывод

На скриншотах показаны два TCP-пакета с разными наборами флагов: ACK и SYN, ACK. В первом случае пакет подтверждает получение данных, во втором — участвует в установлении соединения. Третий скриншот показывает UDP-пакет, его порты и длину.
